This catalog covers every model-facing tool a shipped plugin contributes to `ctx.tools`: the `name`, `description`, and JSON-Schema `parameters` the model receives via the system-prompt assembly. It complements the subsystem pages — this page is the *tools* the agent is offered, not the type definitions behind them.

This catalog is generated from source and covers shipped product tools under `packages/*/tool-*`, each booted with its default config. A completeness guard globs `packages/*/tool-*` and fails if any package is missing from the generator's boot manifest, so a new tool cannot be silently undocumented.

<Note>
  This catalog reflects default config. The registered tool **name** can be a load-time config (e.g. `tool-subagent`'s `toolName`), so a deployment may expose a package under a different or additional name. Per-package notes record those shipped aliases where they exist.
</Note>

## Tool Detail Notes

### `ask_user_question` — `@deepseek-ai/dsh-tool-ask-user`

Pauses the tool call until the active UI provider returns a human answer. Accepts an array of questions, each with a stable `id`, a `question` string, an optional `header`, and optional `options` (choices with `label` and `description`). The `id` field is echoed in the answer for correlation.

### `run_code` — `@deepseek-ai/dsh-tools`

Executes a TypeScript program body against the available tools. Accepts `code` (the body of an async TypeScript function; top-level `await` and `return` work) and `description` (a short summary shown in the UI). Tools are called as `await tools.name(args)` per declarations in the system prompt. Only what the program prints or returns comes back.

### `bash` — `@deepseek-ai/dsh-tool-bash`

Executes a bash command (`bash -c`) and returns stdout/stderr. Each call runs in a fresh shell — no state (cwd, variables, functions) persists between calls. Non-zero exits are reported as `[exit code: N]`. Commands may run under a file sandbox; a blocked file operation is reported as `[sandbox: file access denied under <mode> mode]`. Set `run_in_background: true` for long-running commands; the call returns a job id immediately.

### `str_replace_editor` — `@deepseek-ai/dsh-tool-str-replace-editor`

Standalone view/create/unique literal replace/line insert tool over the filesystem seam. Composes with any shell or terminal API. The read-before-write/edit policy is added by `@deepseek-ai/dsh-fs-observation-policy`.

### `edit`, `read`, `read_image`, `write` — `@deepseek-ai/dsh-tool-fs`

Full filesystem tool suite. `read_image` is not registered without `ctx.attachments`; its schema is route-independent, and execution refuses unless the exact routed model declares image input.

### `glob`, `grep` — `@deepseek-ai/dsh-tool-fs-search`

Unconditional discovery tools that spawn the packaged ripgrep binary (`@vscode/ripgrep`) through `ctx.subprocess` as ordinary foreground calls. No host `rg` install required, no shell layer involved.

### `terminal_*` — `@deepseek-ai/dsh-tool-terminal`

Six opt-in terminal tools complementing one-shot shell/filesystem tools: `terminal_open`, `terminal_close`, `terminal_list`, `terminal_read`, `terminal_send`, `terminal_signal`. `terminal_send(run_in_background: true)` registers with `ctx.jobs`.

### `subagent` / `subagent_fork` — `@deepseek-ai/dsh-tool-subagent`

The registered tool name is the load-time `toolName` config (default `subagent`). The shipped compositions load this package once per subagent backend, so the model additionally sees `subagent_fork` bound to the fork backend. `subagent` is `continuable` (defaults to background with settlement delivery); `subagent_fork` is `one-shot` (defaults to foreground).

### `schedule_create`, `schedule_delete`, `schedule_list` — `@deepseek-ai/dsh-schedule`

Registered only inside live root Agent scopes created after the opt-in Schedule plugin loads. Accepts `after_seconds`, explicit absolute `at`, and bounded fixed-rate `every_seconds`.

### `job_kill`, `job_list`, `job_output` — `@deepseek-ai/dsh-tool-jobs`

Kind-agnostic background-job controller: background bash commands, PTY sends, and subagents are read, listed, and killed through the same three tools.

### `web_fetch`, `web_search` — `@deepseek-ai/dsh-tool-web`

Provider selection stays behind `ctx.web` so model-visible schemas remain stable across backend swaps.

### `ralph` — `@deepseek-ai/dsh-tool-ralph`

A fixed foreground workflow that starts one fresh structured child per round. The model selects only the immutable objective and an optional round cap.
