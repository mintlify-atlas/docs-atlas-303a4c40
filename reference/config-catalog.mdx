Every `config:` block a `cordis.yml` entry can set: for each loadable harness package, the verbatim config declaration (JSDoc included) its `apply` function or service constructor receives, with every referenced type alongside. The paste is the plugin's full declared config type — a field the runtime schema deliberately excludes is a runtime-only seam and is not settable from `cordis.yml`.

<Note>
  This catalog is generated from source (`scripts/gen-config-catalog.ts`) and verified fresh by `pnpm run verify-config-catalog` (part of `doc-sync`). A `Requires:` line lists the service keys the plugin `inject`s: its `cordis.yml` tree must also load providers for those services.
</Note>

## How to Use This Catalog

Each entry in this catalog corresponds to a loadable package. The `config:` fields set in `cordis.yml` configure that plugin when it loads. For example:

```yaml
plugins:
  - package: "@deepseek-ai/dsh-acp"
    config:
      provider: "deepseek"
      model: "deepseek-chat"
```

Every schema-validated key, including nested keys, must be locatable on the declared config type. The generator cross-checks the runtime schemastery schema against the pasted declaration, so the paste cannot hide a loader-accepted field.

<Tip>
  For the service APIs these config types wire up, see the architecture subsystem pages: [LLM Streaming](/architecture/subsystems/llm-streaming), [Tools](/architecture/subsystems/tools), [Sessions](/architecture/subsystems/sessions), and [Sandbox](/architecture/subsystems/sandbox). For the model-facing tool schemas, see the [Tool Catalog](/reference/tool-catalog).
</Tip>

## `@deepseek-ai/dsh-code-runtime-worker-thread`

```ts
/** Plugin config: every execution cap, changeable from `cordis.yml` (no hardcoded tunables). */
export interface Config {
  /**
   * Busy-time budget in milliseconds: the run fails with kind `'timeout'`
   * once the worker's MEASURED event-loop active time exceeds this.
   * Metering measured busy time is what makes the budget both fair (a program
   * awaiting a slow tool accrues nothing) and ungameable (a hot loop accrues
   * whether or not a decoy dispatch is in flight).
   */
  computeMs?: number
  /**
   * Wall-clock ceiling in milliseconds; never pauses for anything. The
   * backstop for what busy-time cannot see (a program awaiting a promise
   * nobody will resolve). At most `2_147_483_647`.
   */
  maxWallMs?: number
  /**
   * Hard cap for serialized log-array, completion-value, and failure-message payloads;
   * fixed result-envelope syntax is excluded.
   */
  maxOutputBytes?: number
  /** The worker's max old-generation heap in MiB; overflow kills the worker, surfacing as kind `'worker-exit'`. */
  maxOldGenerationSizeMb?: number
}
```

## Cordis.yml Example

A minimal `cordis.yml` wiring the ACP bridge with a DeepSeek provider:

```yaml
plugins:
  # LLM adapter — registers the provider route
  - package: "@deepseek-ai/dsh-deepseek-adapter"
    config:
      apiKey: "${DEEPSEEK_API_KEY}"

  # Agent loop — creates the session and drives turns
  - package: "@deepseek-ai/dsh-agent-loop"
    config:
      agents:
        - id: "main"
          cwd: "."

  # ACP bridge — sets provider/model for ACP-created agents
  - package: "@deepseek-ai/dsh-acp"
    config:
      provider: "deepseek"
      model: "deepseek-chat"

  # Bash tool
  - package: "@deepseek-ai/dsh-tool-bash"

  # Filesystem tools
  - package: "@deepseek-ai/dsh-tool-fs"
```
